# JPN-022 — operator content import and publication

## Scope and baseline

The owner selected the V7 relational model on `main` and declined the Hybrid JSONB Published Model in PR #26. This ticket adds a secured local operator CLI and V8 metadata. It uses the JPN-021 v1.0 package format and canonical validator. It does not expose a content-management HTTP route. The public API contract remains the JPN-020 published-only contract. The example package is synthetic and has no production review.

## Schema and reconciliation

V8 adds applied import batches, editorial ownership/version markers, append-only language-review and operator Rights/publication audit tables. Applied batch rows have a null error summary; failed attempts have no durable batch row. Existing V4–V7 revision tables and public APIs are unchanged. Five editorial position constraints become deferrable but remain immediate for ordinary SQL; only an import transaction defers them for stable-key reorder.

The package importer validates with database-aware references and runs in one PostgreSQL transaction. It serializes imports with an advisory transaction lock. It registers a batch only after all inserts/updates succeed. Rights declarations create `unverified` rows; an exact existing declaration may be reused. Changed Rights evidence requires a new key. Media, Item and Lesson roots match global stable keys; Path keys match slugs. Existing roots must be owned by the same package key, have the last imported edit version, and receive a strictly higher semantic package version. Item and Media kinds cannot change. Sections, Stages, Chapters and Chapter Lesson placements match scoped stable keys, retaining identity across reorder. A placement key cannot be reassigned to another Lesson. Tags, media associations, objectives and prerequisites are reconciled within their declared root. Complete Lesson and Path scopes remove absent children when no published historical foreign key prevents removal; such removal otherwise fails and rolls back. Omitted roots or files leave unrelated content untouched.

Idempotency is the sorted filename/length/byte SHA-256 digest of the whole package. Repeating the same package key, version and bytes returns the existing batch ID without writes. The same identity with another digest conflicts. Failed attempts roll back completely and create no durable batch; they can be retried. All counts refer to declared root records. Import never creates revisions or changes public pointers.

## Authorization and reviews

CLI mutations require `CONTENT_OPERATOR_ID` and `CONTENT_OPERATOR_TOKEN_SHA256` in the environment. The CLI reads the token from the console or stdin, never a command argument; `ContentOperatorAuth` verifies SHA-256 with a constant-time digest comparison. The resulting private-constructor principal is required by every mutating service. Ordinary learner sessions grant no operator permission. Provision and rotate a random token in a secret manager or operator shell, update the hash, and restrict database credentials to authorized operators. A compromised database credential can bypass this application boundary; production role provisioning and independent backups remain deployment responsibilities.

Rights clearance is an explicit `unverified → cleared` action; revocation is `cleared → revoked`. The action requires a confirmed operator and records the operator against the V6 append-only Rights event, including timestamp and private source/permission evidence in V6 provenance. Revoked Rights cannot be reapproved. Language review is a separate, explicit operator action for each root edit version. Updating a draft expires that review. Technical validation and parsing never certify language or legal rights. The qualified reviewer is the operator identified by the service credential; organizational review assignment is an owner process outside this repository.

## Publication

Use `preview` to list a candidate edit version and every required dependency key. Supply an explicit positive revision for **each** dependency at publish time; no latest-revision defaults exist. Media has no pins; Item pins Media; Lesson pins Items; Path pins Lessons. Publication locks its root and Rights rows, checks the expected edit version, language review, live Rights and all selected revision eligibility, inserts the relational revision graph, seals it, checks public eligibility, moves the pointer and writes immutable operator/pin audit in one transaction. A draft version can be published once. A failed transaction leaves the previous pointer intact. Publishing a child does not move a parent pin; parent republication is deliberate. V7 continues to evaluate direct and transitive Rights/withdrawal status at read time, so revocation hides affected public content immediately.

Audit and CLI output omit private Rights evidence and token values. Diagnostics use stable codes and the JPN-021 parser's redacted validation report. The CLI returns `0` for success, `1` for validation/conflict, `2` for usage/execution, and `3` for authentication failure.

## Verification and limitations

The isolated PostgreSQL integration tests import the synthetic example, retry idempotently, reject changed content at the same identity, require reviews, publish exact Media/Item/Lesson/Path pins, verify old pins remain stable after v2 publication, check public and contextual routes, confirm revocation hides the Path, and cover rollback, external references, reorder and concurrent attempts. The populated V4→V8 test verifies historical identity/order/publication and a no-op Flyway repeat. Local `nichigo_backend/mvnw.cmd -q verify` on a fresh `jpn021_` PostgreSQL schema passed 65 tests with no failures, errors or skips. Frontend `npm run lint`, `npm run type-check` and `npm run build` passed. The actual operator CLI walkthrough in a separate disposable schema returned `applied` then `already_applied`, recorded reviews, published Item/Lesson/Path v1, served Path/Lesson/Skills HTTP 200, then published Item/Lesson/Path v2 with the older Path pin intact until explicit republishing; Rights revocation changed the Path HTTP result to 404. A denied credential returned exit 3 before creating any schema. The pre-existing JPN-021 resolver test uses a fixed Rights key and requires a fresh schema for a repeated full-suite run.

Media bytes are outside the package and storage delivery remains separate. The CLI does not implement withdrawal; an operator must use an approved maintenance procedure until that action is added. Imports conservatively fail when an omitted child remains referenced by immutable history. Publication currently locks all Rights rows in stable UUID order to guarantee clearance/revocation safety; this can limit throughput as the Rights catalog grows and should be narrowed with an equivalent dependency-closure lock before large-scale authoring. JPN-023 must provide actual reviewed introductory content and owner acceptance before release; these technical tests do not approve the synthetic example for learners.
