# REST API Contract — implemented auth, content, JPN-011 Guest and JPN-033 Skills backend routes

**Base:** `/api/v1`; JSON UTF-8; authenticated identity from server session cookie, not request body. Auth, the five JPN-020 public content GET routes, JPN-021 validation CLI, JPN-022 authenticated local operator CLI, and JPN-023 original draft package are merged in `origin/main`, as are the JPN-011 Guest routes (PR #35) and the JPN-033 Skills Content API routes (PR #36); the frontend does not yet consume the Guest or Skills routes and deployment is not evidenced. The operator CLI is **not an HTTP endpoint**. Other learning routes and the internal HTTP routes below remain proposals. Content errors use the existing flat `{ "code", "message" }` shape. The implemented package format is specified in [the content package contract](02-CONTENT-PACKAGE-CONTRACT.md).

### JPN-020 public content reads (merged in `origin/main`)

- `GET /learning-paths?limit=20&after=<slug>` returns `{ "paths": [{ "id", "slug", "title", "revision" }], "nextCursor": string|null }`. `limit` is 1–50. Results are sorted by stable slug.
- `GET /learning-paths/{slug}` returns `{ id, slug, title, description, revision, stages: [{ id, position, title, description, chapters: [{ id, position, title, description, lessons: [{ id, placementId, slug, position, revision, title, summary }] }] }] }`. Each level has deterministic position ordering. The pinned Lesson revision is included; the response contains no learner-specific station status.
- `GET /learning-paths/{pathSlug}/placements/{placementId}/lesson` returns the same Lesson DTO as `/lessons/{slug}`, resolved from the **current published and eligible Path revision** and its matching placement. The placement's pinned Lesson revision and all its dependencies must remain eligible. Unknown Path, absent/malformed placement, withdrawn identity or revoked required right returns 404. The client cannot choose a Path or Lesson revision; a `revision` query parameter does not override the resolution.
- `GET /lessons/{slug}` returns `{ id, slug, revision, title, summary, objectives: [{ position, kind, text }], sections: [{ id, position, title, items: [{ id, position, content: { id, key, revision, kind, displayTextJa, displayTextVi, payload, media: [{ id, revision, kind, role, mimeType, altTextVi, transcriptVi }] } }] }] }`. `payload` varies by canonical kind. Media storage keys and private rights evidence are never returned.
- `GET /skills/{type}/items?limit=20&after=<stable-key>` returns `{ "items": [{ "id", "key", "revision", "kind", "displayTextJa", "displayTextVi" }], "nextCursor": string|null }`. Current `type` values are `kana`, `vocabulary`, `grammar`, `kanji`, `example`, `dialogue`. This is a content-kind filter; listening/reading/writing/speaking are separate language-skill tags, while flashcards/quizzes are practice/assessment modes, not kinds.

**Access alignment:** eligible reviewed published Skills reads are public for Guests and Users and do not spend a Lesson unlock. Both full Lesson GET routes enforce the Guest unlock in the merged backend (PR #35). The intended split is public path/catalog title, description and navigation metadata versus backend-authorized full Lesson, activities and official Assessment; a separate public objective projection remains pending. A Guest may choose a later Lesson if a daily unlock remains; Users have no product Lesson unlock quota. Direct API access obeys the same gate as the UI. A canonical Skills Item appearing in a Lesson does not grant full Lesson access. Rights and publication checks apply to all reads, including saved Items.

**JPN-011 backend (merged via PR #35):** The [approved Guest Foundation API Contract](../docs/implementation/JPN-011-guest-foundation-contract.md) defines route/DTO/error behavior for identity, active-use retention, quota, first unlock, access status, bookmarks and backend Lesson authorization; the [implementation note](../docs/implementation/JPN-011-guest-foundation-backend.md) records source and test evidence. This backend implementation is merged but not deployed or released, and the frontend does not integrate it yet. Saved pagination includes minimal `unavailable` entries for withdrawn/Rights-ineligible bookmarked Items, allowing Unsave without exposing content; these Items count toward the 20-current-bookmark limit until removed. Guest identity and the 30-minute Auth/CSRF `SESSION` have independent lifecycles; a returning valid Guest can obtain a fresh CSRF token before mutations. Approved retention counts active Guest use, including active public-content viewing, and excludes background polling/prefetch, automatic session/token refresh, CSRF bootstrap alone and idle tabs. `POST /guest/activity` validates the Guest credential, uses server time, applies CSRF and five-minute write throttling, and cannot renew an already expired identity. New content-bearing requests recheck live Rights, and HTTP `no-store` headers reduce stale replay; previously downloaded bytes cannot be reliably recalled. Guest-to-account claim/merge remains **PENDING OWNER DECISION**; deployment-specific SameSite/domain topology remains unfinalized. JPN-032 Assessment transport remains separate and pending.

Both listing routes enforce `limit` 1–50 and a cursor length ≤200; invalid filters return 400 with `invalid_content_query`. Unpublished, withdrawn, rights-invalid and nonexistent detail resources return 404 with `content_not_found`. A Path or Lesson with an invalid required pinned dependency is unavailable as a whole, never silently partial. Database read failures return a generic 503 `content_unavailable`, without SQL details. **Independent Lesson access** returns the Lesson root's current published revision. **Path-contextual access** returns the exact revision pinned by a placement in the current published Path, even if the Lesson root has since advanced. Historical audit access is deferred to an authorized internal JPN-032/JPN-022 design; there is no unrestricted historical-revision public route. Public reads resolve only sealed revisions and live rights status in a repeatable-read transaction. Publication/withdrawal endpoints and a media delivery URL are **not** implemented in JPN-020.

**Media revocation boundary:** These responses expose metadata only; they do not issue a media URL or expose a storage key. A future delivery endpoint must recheck live Media/Item eligibility before each authorization or signed-URL issuance and deny new access after revocation or withdrawal. Use private storage with an authorization proxy or short-lived signed URLs. A URL or downloaded byte already issued cannot be recalled by these database checks; its maximum lifetime and cache behavior must be approved before media delivery launches. Rights events and private evidence are never public response fields.

**JPN-033 stroke byte delivery (Draft PR scope, not released):** `GET /api/v1/skills/kanji/{itemId}/stroke-asset` is an anonymous public read of the current eligible Kanji revision's exact pinned `writing`/`stroke-order` Media revision. It accepts no storage key or revision parameter. Backend checks current Kanji/Media publication, withdrawal and Rights, then verifies bounded private JSON bytes against the pinned checksum, glyph and versioned stroke contract before returning them. `200` uses `application/json`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`; unavailable/ineligible Kanji or stroke yields `404 content_not_found`; missing/corrupt private bytes yield `503 content_unavailable`. Error responses also use `no-store`. No signed URL or private key is returned. Already delivered bytes cannot be recalled. Production delivery requires an approved private persistent mount and approved asset Rights.

**JPN-033 Kanji v2b backend branch:** `GET /skills/kanji/{itemId}` returns canonical Kanji `id`, `key`, `revision`, `glyph`, `meaningVi`, `onReadings`, `kunReadings`, ordered `relatedVocabulary` and `strokeOrder`. Each Vocabulary has canonical `id`, `key`, pinned `revision`, `surface`, `reading`, `glossVi` and eligible `examples`; each Example has canonical identity, pinned revision, `textJa`, `translationVi` and authored `segments: [{text, reading?}]`. Only Example revisions explicitly marked `kanjiDetailCandidate: "yes"` and reviewed through the operator pipeline enter this presentation. Runtime filtering rechecks Rights on each pinned target without changing the pin; no raw `exampleRefs` or `itemRefs` are exposed. Revoking related Vocabulary or Example removes only that entry. Revoking Kanji itself returns 404. `strokeOrder` is `metadata_only` with eligible Media id/revision/MIME/alt text or `unavailable` with null fields. There is **no byte-delivery URL** in this response; The byte-delivery endpoint is a separate Draft PR scope. All responses are anonymous public reads with `Cache-Control: no-store`; the Kanji v2b foundation merged via PR #42 and is not released.

Until detail pagination is designed, the backend refuses a Path larger than 100 Stages, 100 Chapters or 1,000 placements and a Lesson larger than 100 Sections, 1,000 Items, 1,000 Objectives or 5,000 media references with the generic 503 response. JPN-022 must reject such a candidate before publication; this is a protective API bound, not an approved curriculum size.

**Approved learning behavior:** a Guest consumes one of 2 new Lesson unlocks on the Asia/Ho_Chi_Minh date only for the first Start Learning of that Lesson. Revisit, Practice, completion and Assessment retries cost nothing; prior unlocks remain available while identity/data are valid. Unused allowance does not roll over. Unlock and bookmark limits are enforced atomically under concurrent requests in the merged JPN-011 backend (PR #35). Authenticated Users have neither product limit. Guest identity/data persist server-side with cleanup eligibility 90 days after the latest active Guest use, plus the approved technical five-minute precision margin; Guest-to-account claim/merge policy remains pending. Completion, official Assessment results, bookmarks and Item mastery remain separate.

**JPN-032 PENDING CONTRACT:** five v1 Activity types are Single Choice, Matching Pairs, Fill in the Blank, Ordering and Typed Answer. Practice offers immediate retry/feedback without an official grade. Lesson Assessment exists only where configured and uses reviewed published Activity revisions, equal full-or-zero weights, server-side >=80% pass, unlimited retries, question/order rotation with fallback reuse, and configurable size (typically 5 or 8–10). Start pins exact Lesson/Question revisions; save/resume holds authoritative in-progress work, reconciles temporary offline drafts and rejects stale overwrites. Submission waits for synchronized answers and is idempotent; latest/best persisted results and prior earned pass survive later failure. Keys/accepted answers/explanations remain private until full submission. Typed answers use authored alternatives and controlled normalization without equating scripts. Rights loss stops affected unfinished work without a failed grade, while valid prior results remain. Exact route, DTO, version token, conflict codes, offline draft storage, deliberate restart lifecycle and incomplete-attempt retention are pending. Passing completes an Assessment-required Lesson; a Lesson without one needs explicit completion.

**Vocabulary FE-first presentation mapping (CONTRACT MISMATCH / INTEGRATION GAP):** the merged JPN-036 frontend uses demo `surface`, `reading`, `meaningVi`, `romaji`, `topicId`, `partOfSpeech`, `exampleJa`, `exampleVi` and `exampleRomaji`. The published Skills list currently exposes stable `id`/`key`/`revision`/`kind` and `displayTextJa`/`displayTextVi`, not those named FE fields. Canonical vocabulary payload stores `surface`, `reading`, `glossVi` (the source for a reviewed `meaningVi` presentation) and optional `exampleRefs`; Item `topics` can inform a reviewed topic mapping. The public Lesson detail DTO contains canonical `payload`, but is not a Skills detail endpoint and must be Guest-gated. `romaji`, `partOfSpeech`, `exampleJa`, `exampleVi`, `exampleRomaji` and FE `topicId` are not guaranteed published fields; the demo supplies them today. Approved, reviewed content and an API/adapter contract are required before populating them; do not synthesize values. Preserve the existing FE components through a presentation DTO/adapter over relational canonical content and immutable revisions, without replacing the database model. Stable Lesson, placement, Section/Section Item, Item, Activity and attempt identities must come from the backend; visual order/index is not identity. Existing auth cookie/CSRF is a reusable foundation. Quick Check client evaluation, `correctIndex`, `evaluateQuiz`, immediate feedback and its demo cooldown are valid for that separate Skills flow, not an official Assessment contract.

**Idempotency:** proposed lesson completion is uniquely keyed by actor/lesson; repeated calls must not double count. Assessment duplicate submission must create one official grade. JPN-022's implemented operator import uses package key, version and content digest for idempotency. Do not trust client-provided grade, quota date or user ID.

**Tour:** `status = not_started | in_progress | completed | skipped`; `tourVersion` and `lastStep` allow future updates. Guest server-side persistence and 90-day inactivity retention are approved but unimplemented.

**Open:** production cookie/domain topology, password reset/verification, Guest-to-account claim/merge semantics (**PENDING OWNER DECISION**), any future HTTP operator transport, non-JPN-011 learning route/DTO/error/version/conflict shapes, Assessment restart and incomplete-attempt retention, Chapter Review and mastery policy. JPN-011 backend is implemented and merged (PR #35); FE integration and production deployment are unverified. JPN-022 already provides authenticated local operator transport; its CLI does not imply an HTTP operator API.
