## Data model and import

V10 adds `content_item_edges` for ordered Kanji→Vocabulary and Vocabulary→Example draft relationships and `content_item_revision_edges` with composite foreign keys to exact published source and target revisions. A revision-child trigger rejects updates/deletes and additions after the source revision is sealed. A kind trigger restricts each edge role to its canonical Item kinds, preventing relationship cycles. Draft edges are reconciled by package import after all Items are available. Existing batch checksum, ownership and edit-version checks remain in force.

Package 1.1 is a separate set of closed schemas; package 1.0 remains accepted with its original schema. Kanji `relatedVocabularyRefs` and Vocabulary `exampleRefs` are ordered arrays of stable keys in 1.1. A 1.0 update of a package-owned Item preserves existing draft Item edges because it cannot express their replacement. A 1.1 update replaces the Item's complete draft edge list; an empty or omitted relationship field clears it. Both use existing package ownership, edit-version and checksum rules, and neither changes sealed published edges. Operator preview requires `item:<target-key>` pins in addition to existing bare Media keys. First Kanji publication checks for at least one related Vocabulary and requires every chosen target to have a published, sealed, Rights-eligible revision. The revision edge does not move when the target publishes a newer revision.

Example 1.1 `segments` hold authored text and optional reading. Schema and semantic validation reject empty or whitespace-only text/reading; concatenated segment text must equal `textJa`. `kanjiDetailCandidate: "yes"` requires at least one nonblank reading. The Kanji Detail projection uses the same structural check, while the existing per-edit-version operator language review remains the human gate for semantic Furigana completeness. An Example without this candidate marker can be valid and published but is omitted from Kanji Detail.

## Public API and Rights

`GET /api/v1/skills/kanji/{itemId}` uses the current eligible Kanji revision. It resolves ordered pinned Vocabulary and Example revisions, filtering each by live Rights and publication status. Missing or revoked related Items produce empty child lists without replacing the pins or hiding Kanji. Direct Kanji revocation returns 404. The response exposes canonical identities, revisions, glyph/meaning/readings, Vocabulary presentation fields and structured Example segments. It does not return raw Item reference keys or Rights evidence.

Kanji stroke Media uses the existing `writing` kind and `stroke-order` role. V10 exempts only that role/kind on a Kanji revision from the otherwise mandatory Item Media eligibility gate and applies the same exception to V7's set-based Path check. The Lesson Media projection filters revoked Media metadata. Kanji Detail returns eligible stroke metadata with `status: metadata_only`, or `status: unavailable` and null fields. It returns no storage key or byte URL; bytes are served only by the separate Rights-gated `stroke-asset` route described under "Stroke byte delivery follow-up". Previously downloaded bytes cannot be recalled. AnimCJK Kanji asset provenance and Arphic Public License obligations remain pending review; no asset was imported or cleared here.

## Stroke byte delivery follow-up (Draft PR scope)

An authenticated `stroke ingest <media-key> <kanji-key> <asset-path> --confirm` CLI action stages at most 256 KiB of version 1 JSON against the current `writing` Media draft's storage key, SHA-256 and linked Kanji glyph. It uses the existing operator token on stdin; no HTTP upload exists. Configure `STROKE_STORAGE_ROOT` as an existing absolute private directory outside static/public roots. An unset or invalid root fails closed; deployment must provide an approved persistent private mount. The adapter writes a temporary file in the destination directory and uses an atomic hard-link create to publish immutable bytes without replacing an existing key; unsupported filesystems fail closed. It checks symlinks, size and checksum on each read. Storage is behind `StrokeAssetStorage` for a later approved adapter.

`content/schemas/stroke-asset-v1.schema.json` defines glyph/codepoint, viewBox, count, ordered outline paths, number positions and optional arrows. The server validator additionally enforces 256 KiB, 64 strokes, 16 paths per stroke, 256 total paths, 8192 characters per path, JSON nesting depth 12, coordinate bounds and a path command allowlist. JSON contains no SVG markup, scripts or external references. Provenance remains in existing Media/Rights records; reviewers must verify arrows and source permission before clearance. No automatic arrow inference occurs. Media metadata may publish as before, but a Kanji Item publication pinning a stroke fails if its bytes are absent or invalid. Other Media behavior is unchanged.

`GET /api/v1/skills/kanji/{itemId}/stroke-asset` resolves current Kanji and exact pinned Media revision, checks live eligibility, reads bounded bytes and verifies hash/JSON before responding. It returns `application/json`, `nosniff`, `no-store`; ineligible content returns 404 and missing/corrupt bytes 503. Existing Kanji Detail remains metadata-only and available when optional stroke Rights are revoked. Downloaded bytes cannot be recalled. No production storage mount or Kanji asset Rights have been approved; FE integration and release remain pending.

Compatibility boundary: package 1.0/1.1 metadata import and publication of non-stroke Media are unchanged. A new Kanji revision that pins `stroke-order` Media now needs staged JSON bytes, so legacy PNG/SVG stroke metadata must be migrated to reviewed JSON before that Kanji can be republished with the stroke. Already sealed Kanji revisions remain immutable and Kanji Detail remains available; the new byte route returns 404 for a pinned stroke with a non-JSON MIME. This narrow change does not alter Lesson/Path or required Media Rights gates.

### Security review fixes

Stroke path validation now resolves absolute and relative M/L/H/V/C/S/Q/T/Z commands, including smooth Bézier reflection. It checks move/end points and actual quadratic/cubic extrema against the viewBox with a margin of `max(24, 5% of the larger viewBox dimension)`; Bézier control points may lie outside. Numeric operands retain a separate 1,000,000 arithmetic ceiling. This is a bounded static geometry check, not an SVG renderer or proof of correct stroke shape, ordering or arrow placement. Editorial review remains mandatory. The margin and supported command subset must be checked against each proposed production data source before approval; no production AnimCJK data was imported.

Filesystem threat model: public HTTP clients cannot select keys, write the private root or alter metadata; the operator CLI and service account are trusted. **Mandatory deployment condition:** the private root and every ancestor through its mount point must permit write/delete/rename only to trusted service/operator identities and administrators. Shared writable directories, untrusted local users and mutable mounts are outside the supported model. The adapter rejects path traversal and symlinks, checks real-path containment and file identity before/after bounded reads, serializes its own writes, and atomically creates a hard link instead of overwriting an existing target. Delivery validates the copied bytes against the pinned SHA-256 and JSON before response. `SecureDirectoryStream` was assessed but is not portable to the Windows/NIO filesystem used for local testing and offers no hard-link create primitive for the current immutable write. The path checks do **not** remove TOCTOU when an attacker can rename a parent directory concurrently. Under that condition a write could be redirected before the post-check; production must not enable this adapter on such a mount. Verify ACLs, mount ownership and hard-link behavior during deployment review.
